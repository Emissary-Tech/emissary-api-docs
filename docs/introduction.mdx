# Emissary documentation

**Emissary** is a platform for **LLM model routing, post-training and inference**. Route each request
to the model best suited to handle it, post-train models of your own on your data, and serve base and
fine-tuned models on managed GPU infrastructure. Emissary replaces slow, expensive frontier-model
calls with small, purpose-built classifiers that return the same decision in milliseconds for a
fraction of the cost, with no prompt engineering and no full-size model in the loop.

## Quickstart

The fastest way to get started is one of our quick start guides. Each walks you through building
your first model three ways: the public playground (no signup), the dashboard UI, and the API.

- **[Create Your First Judge](./quickstart/llm-as-judge)**: score any text against criteria you
  define (for example *helpfulness* or *factual accuracy*) and get back a calibrated probability
  instead of a vague verdict.
- **[Create Your First ModelRouter](./quickstart/router)**: automatically send each query to the
  model best suited to handle it, so you stop hard-coding one model for every request.

Want a router that also accounts for cache state, effort and output length? Start with
[model routing: get started](./routing/get-started). Want to train your own models? See the
[post-training quickstart](./fine-tuning/quickstart).

## How do the pieces fit together?

Routing, post-training and inference form a loop. Every routed request leaves a trajectory, so you
learn which requests are easy and which no model can handle. You serve the open models you rely on
from dedicated capacity, and you post-train models of your own on that traffic. The router sends work
to them when they're the better call, which makes routing cheaper again. See
[what emerges from routing](./routing/insights).
